# 리팩토링 브랜치·PR 구성

**두 단계씩 묶은 브랜치와 작업 단위별 커밋을 유지하고, 세 개의 연결된 PR로 공유한다.** RF-01~06 구현과 당시 검증은 [RF-05/06 기록](rf05-06-verification.md)에 정리했다. 최종 JUnit 154개·빌드·native 전체 입력 검사는 통과했으며, 상세 결과는 [최신 검증 기록](native-focus-fix.md)을 확인한다.

| 묶음 | 범위 | 브랜치 | PR 대상 |
|---|---|---|---|
| 1 | RF-01 기존 동작 고정 + RF-02 입력·생명주기 분리 | `refactor/rf01-02-controller` | `main` |
| 2 | RF-03 일반 엔진 + RF-04 아이템·효과 상태 | `refactor/rf03-04-engine` | `refactor/rf01-02-controller` |
| 3 | RF-05 화면 연결 + RF-06 독립 엔진·테스트 정리 | `refactor/rf05-06-integration` | `refactor/rf03-04-engine` |

앞 묶음의 변경이 뒤 묶음의 기반이다. 각 PR은 바로 앞 브랜치를 대상으로 하므로 해당 묶음의 차이만 보여준다. 리뷰·병합 순서는 1 → 2 → 3이다. 앞 PR 병합 뒤 다음 PR의 대상을 main으로 바꾸고, squash/rebase로 병합했다면 중복 변경이 남지 않도록 커밋 기반도 정리한 뒤 검사한다. PR 생성과 병합은 구분하며, 병합은 팀 리뷰 후 별도로 진행한다.

병렬 개발 시 서로 다른 worktree를 사용하고, 묶음 검증 전에 앞 브랜치의 최종 커밋을 반영한다. 제품 기능은 Classic/Item 1인 게임과 두 엔진 독립 검증까지다. 실제 대전·공격·P2P는 포함하지 않는다.

검증은 묶음마다 JUnit·빌드·커버리지를 확인하고, 마지막에는 실제 창의 표시·키·pause·종료·기록 흐름을 확인한다. native Robot 검사는 사용자의 마우스·키보드 조작에 영향을 받으므로 실행 전에 알리고 합성 입력 검사와 결과를 구분한다.
